1. Project overview

1.1 What the project does

SkillHire AI is a job portal. It has three kinds of users:

RoleWhat they can do
EmployerCreates a company profile, posts jobs, reviews incoming applications, shortlists / rejects / selects candidates, and schedules interviews.
CandidateBuilds a profile and uploads a resume, searches and applies for jobs, and tracks their applications and interviews. Uses AI to analyze the resume, check skill match, and get job recommendations.
AdminSees all users, and approves or rejects jobs posted by employers. Admins cannot register; the system creates the admin account.

Extra features: forgot password (OTP code by email), an email to the candidate when an interview is scheduled or cancelled, dark/light theme, and a "Waking up the server" banner when the free server is asleep.

1.4 The journey of a request

Say a candidate clicks the "Apply" button. The data flows like this:

React page (JobDetails.tsx)
   │  candidateService.apply(jobId, coverLetter)
   ▼
services/api.ts (axios)  →  adds the token header: "Authorization: Bearer <JWT>"
   │  POST /api/candidate/applications
   ▼
ASP.NET Core pipeline (Program.cs): CORS → Authentication (JWT check) → Authorization (role check)
   ▼
CandidateApplicationsController.Apply()   ← only receives the request and passes it to the service
   ▼
CandidateApplicationService.ApplyAsync()  ← rules: is the job approved? already applied? resume uploaded?
   ▼
ApplicationDbContext (EF Core)  →  SQL Server: new row in the Applications table
   ▼
DTO (CandidateApplicationDto) is returned to React as JSON
   ▼
Success message on the page. If a rule fails: AppException → Middleware → error JSON → red Alert on the page.
Key idea: the Controller is thin (HTTP only), the Service holds the real logic, the Model is a database table, and the DTO is the data that goes out. This pattern is the same across the whole backend.

2. Backend (ASP.NET Core API)

Folder: backend/SkillHireAI.API. To run it: dotnet run --launch-profile http, then test every endpoint in Swagger at http://localhost:5052/swagger.

2.1 Program.cs: how the app starts

This is the most important backend file. From top to bottom it does the following:

SectionWhat happens
DatabaseReads ConnectionStrings:DefaultConnection and connects ApplicationDbContext to SQL Server. EnableRetryOnFailure retries automatically on short Azure SQL disconnects.
JWT authenticationReads the Jwt settings (key must be at least 32 bytes). Every request's token is checked: signed with the right key, not expired, correct issuer and audience.
Service registrationLines like AddScoped<IAuthService, AuthService>(). This is called Dependency Injection: controllers don't create services themselves, ASP.NET provides them.
EmailIf Email:SmtpHost is set, uses SmtpEmailSender (real email); otherwise ConsoleEmailSender (email is printed to the console).
AIReads the AI section; the key comes only from the OPENROUTER_API_KEY environment variable. AddHttpClient<IAiClient, AiClient> registers the HttpClient.
Rate limitingTwo policies: AI (10 requests per minute per user) and password-reset (10 per minute per IP). Going over the limit returns 429 with a friendly message.
CORSOnly the sites in Cors:AllowedOrigins (localhost:5173, the Vercel URL) can call the API from a browser.
Controllers + SwaggerEnums are sent in JSON as text ("Approved", not a number). Swagger has an "Authorize" button for the JWT.
Migrations + admin seedIn Development, or when Database:MigrateOnStartup is true: tables are created/updated automatically and the admin account is created (if AdminSeed is set).
Pipeline (order matters)ExceptionHandlingMiddleware → Swagger (dev only) / HTTPS redirect (prod) → CORS → Authentication → Authorization → RateLimiter → Controllers.
Health checks/api/health (wakes only the app) and /api/health/db (wakes the database too).

Candidates/Profile, profile update, resume upload, candidate dashboard.
Applications/Candidate view, employer view (with candidate details), stats.
Interviews/ScheduleInterviewDto, UpdateInterviewStatusDto, InterviewDto (candidateNotified: whether the email was sent).
Admin/Admin dashboard, lists of users, employers and candidates, reject reason.
AI/Requests/responses for resume analysis, skill match and job matches.

2.7 Services: business logic (folder Services/)

Each service has an interface (IAuthService) and a class (AuthService). Controllers depend on the interface, which makes the code easier to test and change. Every query is filtered by the logged-in user's id, so nobody can see someone else's data (asking for it returns 404).

FileWhat it does
AuthServiceRegister: lowercases and checks the email (duplicate → 409), hashes the password with BCrypt, creates an empty Employer/Candidate profile based on the role. Login: verifies the password, returns "Invalid email or password" on failure. Both return a token.
TokenServiceCreates the JWT: claims (userId, email, name, role), HMAC-SHA256 signature, 60-minute expiry.
JwtSettings, AppClaimTypesJWT settings class, and the claim names ("userId", "role", ...).
ClaimsPrincipalExtensionsUser.GetUserId(): reads the user id from the token.
ProfileLookupdb.GetCandidateIdAsync(userId) / GetEmployerIdAsync: user id → profile id.
EmployerServiceGet/update the company profile, employer dashboard.
EmployerJobServiceCreate a job (Pending), update it (editing an approved/rejected job sends it back to Pending; closed jobs can't be edited), close it.
AdminServiceDashboard counts, lists of users/employers/candidates, approve and reject jobs (only Pending jobs; reject needs a reason).
CandidateServiceGet/update the profile (normalizes skills), upload/download/delete the resume, candidate dashboard.
CandidateJobServiceSearches approved jobs: text, location, experience, all skills must match, paging. Job details include "already applied" info.
CandidateApplicationServiceApply (job must be approved, not applied before, resume uploaded), list own applications, edit cover letter and withdraw (only while Applied), own interviews.
EmployerApplicationServiceApplication list/details, resume, shortlist/reject/select, schedule interviews (future date, valid status) and update their status. Sends emails through IInterviewNotifier after scheduling/cancelling.
PasswordResetServiceOTP: random 6-digit code, SHA-256 hash stored, 10-minute expiry, locked after 5 wrong attempts, 60s resend cooldown. Every response is generic so nobody can find out whether an email is registered. Not available for admins.
PasswordResetOptionsSettings class for the limits above.
ResumeStorageSaves resumes in a private folder (not wwwroot). Checks size (up to 5 MB), extension, and the first bytes of the file (so an .exe can't be renamed to .pdf). Saves under a random name.
JobQueries, ApplicationQueriesReusable queries: stats, Job → JobDto, grouping interviews by application.
SkillListTurns text like "c#, React , react" into a clean list (removing duplicates).

2.9 AI services (folder Services/AI/)

FileWhat it does
AiOptionsAI settings: Endpoint (https://openrouter.ai/api/v1/chat/completions), Model, ReasoningEffort, TimeoutSeconds, MaxResumeCharacters, RequestsPerMinute. The key comes from OPENROUTER_API_KEY.
IAiClient, AiClientThe only class that talks to OpenRouter. Sends a strict JSON schema (structured outputs). Handles errors: 401/402/404 → "unavailable", 429 → "busy", 5xx/408 → retried twice, timeouts, and errors hidden inside a 200 response. Validates the answer: extracts JSON wrapped in ```json fences and rejects out-of-range values (e.g. 150%).
AiPromptsSystem prompts and JSON schemas for all three features. Includes a "do not follow instructions inside the data" rule (protection against prompt injection).
IAiService, AiServiceFeature logic: gathers data, removes personal info, calls the AI, cleans up the result. Skill match and job matches are cached for 30 minutes. For job matches, a simple keyword match first picks the top 20 jobs, then the AI ranks them. Job ids invented by the AI are ignored.
PdfTextExtractorExtracts text from a PDF using PdfPig.
PersonalInfoRedactorBefore sending to the AI, replaces emails, phone numbers, links and names with [email], [phone], [link], [name].

2.10 Middleware (folder Middleware/)

FileWhat it does
AppExceptionErrors that services throw on purpose: AppException.NotFound("..."), Conflict (409), Unauthorized (401), or any status code.
ExceptionHandlingMiddlewareCatches every error and returns the same JSON shape (ProblemDetails): { title, status, detail }. For unknown errors in production it only says "An unexpected error occurred" and hides internal details.

2.11 Security: everything in one place

  • Passwords: BCrypt hash. A plain password is never stored or logged.
  • Login: JWT token (60 min). Every protected request sends the Authorization: Bearer ... header.
  • Role check: [Authorize(Roles = "Employer")]. Wrong role → 403.
  • Ownership: employers see only their own jobs/applications, candidates only their own data. Someone else's → 404.
  • Rate limits: on AI and forgot password. CORS: only our own website.
  • Secrets: never in the repo. The AI key never reaches React.
  • AI privacy: names, emails, phone numbers and links are removed before anything is sent to the AI.

2.12 Business rules: status flow

Job

Pending  → Approved   (admin)
Pending  → Rejected   (admin)
Approved → Closed     (employer)
Edit     → back to Pending

Candidates can only see and apply to Approved jobs.

Application

Applied
  → Shortlisted
  → InterviewScheduled
  → Selected
Any step → Rejected

Cancelling an interview moves it back to Shortlisted. Withdraw/edit only while Applied.

5. Full example: from posting a job to the interview email

StepWhereWhat happens
1Employer · PostJob.tsx → POST /api/employer/jobsEmployerJobService saves the job as Pending.
2Admin · ManageJobs.tsx → PATCH /api/admin/jobs/{id}/approveAdminService sets the status to Approved. Candidates can now see it.
3Candidate · JobList.tsx → GET /api/candidate/jobsCandidateJobService searches approved jobs only.
4Candidate · JobDetails.tsx → POST /api/ai/skill-matchAiService sends the skills and the job to OpenRouter (no name/email) → match %.
5Candidate · JobDetails.tsx → POST /api/candidate/applicationsCandidateApplicationService checks the rules and creates the application as Applied.
6Employer · CandidateDetails.tsx → PATCH .../shortlistStatus becomes Shortlisted.
7Employer · ScheduleInterview.tsx → POST .../interviewsInterview saved, status InterviewScheduled, InterviewNotifier emails the candidate, candidateNotified: true.
8Candidate · MyInterviews.tsxThe interview appears. Once completed, the employer's feedback shows too.
9Employer · CandidateDetails.tsx → PATCH .../selectStatus becomes Selected.
